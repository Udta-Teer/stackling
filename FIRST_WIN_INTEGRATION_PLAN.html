STACKLING / PRODUCT FLOW

Integrate the first win without making it feel like onboarding.

The learner should experience one continuous app. The load-balancer win is the first node in the curriculum path, not a promotional demo parked beside it.

Locked transition: “You just routed requests across servers. Now follow one of those requests from your phone to the server.” This makes Unit 1 feel like the next layer of the same system.

The first-use journey

1 · ACTAdd one load balancer and see 30 queued req/s fall to zero.
2 · NAMERecap the capability: routing made existing capacity reachable.
3 · BRIDGEConnect the win to the journey of a request.
4 · CONTINUEOpen Unit 1, Lesson 1 inside the same shell.

The handoff screen

What the learner sees

You made your first system-design decision.

“A load balancer made Server B reachable, so both servers could share the work. But how did those 90 requests reach your system in the first place?”

Primary action: Continue: Follow a request

Secondary action: Replay this win

Do not interrupt momentum
  • No lesson picker or 32-unit inventory
  • No account or email form
  • No paywall before the learner enters the curriculum
  • No streak, hearts, XP, or notifications
  • No second concept explanation
  • No choice about what to learn next

Purchase rules
  • No email or account required before purchase.
  • Use App Store or Play Store entitlement as the initial identity.
  • Offer Restore Purchases.
  • Ask for an account only later if the learner requests cross-device sync.
  • Do not start the trial automatically.
  • Do not hide the post-trial price.
Why after Lesson 1: the first win proves the app is interactive; the first foundation lesson proves it can teach. Asking earlier sells a trick. Asking much later wastes the strongest purchase window.

Duolingo-style gamification integration

1 · SOLVEThe queue falls from 30 req/s to zero.
2 · REACTThe Stackling mascot snaps a new block into place.
3 · REWARD+10 XP and “First system improved.”
4 · PATHThe Prologue node fills and connects to Unit 1.
5 · MOVEContinue directly into “Follow a request.”
First-session rewards
  • The first win is the path’s Prologue node.
  • Success fills the node; it does not merely show a modal.
  • The mascot reacts to the actual mechanism: an idle blue server wakes up and the amber Stackling adds the routing layer.
  • A short sound/haptic and progress animation reinforce the result in Expo.
  • XP records completed practice, never claims mastery.
  • No streak-loss warning appears on day one.
Lesson 1 completion sequence
  1. Correct-answer explanation lands.
  2. Lesson-complete animation plays.
  3. +20 XP is banked.
  4. Day-one streak begins.
  5. The next path node unlocks visibly.
  6. Only then does the trial paywall appear.
Returning loop
  • Path opens at the next recommended node.
  • Daily goal mixes one new lesson with due review.
  • Streak rewards returning; missing a day never deletes learning progress.
  • Milestones celebrate completed mechanisms and systems.
  • Adaptive review can restore a cracked skill node.
Not in the first release
  • Leagues or public ranking
  • Gems, shops, and multiple currencies
  • Punitive hearts that stop learning
  • Loot boxes or random rewards
  • Notification pressure before demonstrated value
  • XP presented as system-design ability
Paywall relationship: rewards are granted before the offer. The learner sees that progress is safely theirs, then sees the locked path ahead. Subscription unlocks the journey; it does not ransom the success they just earned.

HTML prototype architecture

One shell
  • lesson.html becomes the prototype entry point.
  • Add a full-screen first-win view beside picker, lesson, feedback, and completion views.
  • Move the accepted interaction into a renderer; do not iframe or redirect to first-session.html.
  • The completion action calls the existing lesson boot path directly.
  • first-session.html remains a focused review fixture, generated from the same data.
One content source
  • Create content/onboarding/first-win.json.
  • Store scenario numbers, labels, diagram nodes, before/after loads, bridge copy, and destination lesson.
  • Validate that incoming traffic, server capacity, splits, completing rate, and queue rate reconcile.
  • Render the same JSON in HTML now and Expo later.

Implementation order

Extract the experience into data

Create the onboarding schema and arithmetic validator before copying UI into the app shell.

Add a first-win view to the lesson shell

Reuse Stackling tokens, header, progress treatment, guarded storage, focus handling, and reduced-motion behavior.

Add the boot gate

New learner → first win. Completed learner → last position. #review → picker. No redirect flash.

Build the handoff

Continue directly into Unit 1 Lesson 1 with the request-journey bridge. Preserve keyboard focus and scroll position.

Add restart and recovery

Replay from the picker, reset safely, survive reload, and work when localStorage throws on file://.

Prove the continuous journey

Browser test first launch → action → success → handoff → first concept → exit → reload → resume. Test at 360px and 430px.

Dismissing it preserves progress; opening the next paid lesson reopens the offer. A successful or restored purchase unlocks paid content.
