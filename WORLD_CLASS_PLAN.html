First-Session Aha Experience

Open the accepted prototype → One familiar problem, one architecture decision, and one immediate measured success on a phone.

Accepted flow
  • 90 req/s enters the system
  • Two servers each have 60 req/s capacity
  • Direct routing overloads Server A while Server B is idle
  • The learner adds one load balancer
  • Traffic becomes 45/45 and the queue falls to zero
  • The explanation distinguishes routing from creating capacity
Activation rule
  • One mechanism per first-touch experience
  • One meaningful learner action
  • Inputs and capacity stated before action
  • Numerical before/after result
  • No trivia, punishment, or subscription interruption
  • No second experiment disguised as continuation

01

Guided Design Studio

Create a free-form but structured workspace where the learner owns one complete design.

Build
  • Ambiguous prompt and clarification stage
  • Functional/non-functional requirements
  • Traffic and storage estimates
  • API and data-model notes
  • Free-position architecture canvas
  • Failure analysis and tradeoff defense
  • Autosave and resume
Do not fake
  • No component slots revealing the topology
  • No single hidden “correct diagram”
  • No keyword score presented as intelligence
  • No AI dependency in the first offline prototype
Acceptance: a learner can complete URL Shortener from an empty canvas, save it, revise it, and compare it against an explicit rubric without seeing the reference design first.
02

Evidence-Based Evaluation Rubric

Score observable design evidence, not whether the diagram matches one reference picture.

Rubric dimensions
  • Requirement coverage
  • Estimation and assumptions
  • API/data model coherence
  • Scale path and bottlenecks
  • Consistency and failure handling
  • Security, cost, and operations
  • Tradeoff communication
Feedback model
  • Evidence cited from the learner’s work
  • Missing requirement identified
  • Consequence of each risky choice
  • One next action, not a solution dump
  • Human-reviewed exemplar scores
Acceptance: two materially different valid designs can both pass, while a design with an unhandled single point of failure receives a specific, reproducible deduction.

03

Concept-Level Mastery Model

Tag every exercise with the concepts and reasoning skills it provides evidence about.

Track
  • Correctness, attempts, latency, hints
  • Specific wrong choice or wrong placement
  • Confidence and answer changes
  • Last successful retrieval
  • Performance across novel contexts
Model separately
  • Recall of definitions
  • Mechanism understanding
  • Application
  • Diagnosis
  • Open-ended design
Acceptance: “Caching 82%” cannot be earned solely through definition questions; application and failure-mode evidence are required.
04

Adaptive Spaced Review

Generate review sessions from learner evidence instead of replaying fixed checkpoint files.

Review rules
  • Requeue misses quickly
  • Increase intervals after successful retrieval
  • Mix related and confusable concepts
  • Prefer transfer questions over duplicates
  • Resurface prerequisites behind later errors
Review experience
  • Daily 5-minute weak-skill session
  • Why an item is being reviewed
  • Overdue concept count
  • Offline scheduling
  • No punishment for returning late
Acceptance: two learners completing the same unit receive different review queues based on their errors and elapsed time.
05

Guidance Fading

Move learners from worked examples to independent architecture without abandoning beginners.

Acceptance: each capstone supports five levels: worked design → partial completion → palette build → empty canvas → timed independent design. Experienced learners can test out of early levels.

06

Requirement Changes & Failure Injection

Apply new constraints to the learner’s existing design: traffic spikes, region loss, deletion deadlines, celebrity fan-out, cost cuts, abuse, and stale replicas.

Acceptance: every capstone contains at least three requirement changes and two failures that force a meaningful revision.
07

Expand to 15–20 Deep Capstones

Add File Storage, Video Streaming, Search Autocomplete, Notifications, Payments, Metrics, Web Crawler, Scheduler, Email, Collaborative Editing, Ticket Booking, and Object Storage.

Acceptance: each capstone follows requirements → estimates → APIs/data → architecture → deep dive → failures → operations → revision; no capstone is a renamed multiple-choice unit.
08

Simulations and Executable Labs

Let learners manipulate cache hit rate, queue backlog, replication lag, retry storms, partitions, query plans, and connection pools.

Acceptance reached: the curriculum contains 30 causal simulations across flow/offload, time-based backlog, retry amplification, and dynamic worker/pool-capacity models. Six broader executable labs remain a separate interaction milestone.

09

Contextual Tutor

A tutor that sees the current lesson, the learner’s design, previous mistakes, and rubric. It asks guiding questions and cites the evidence behind feedback.

Acceptance: tutor feedback distinguishes two different wrong architectures and never reveals a complete solution before the learner requests it.
10

Timed Mock Interviews and Verbal Defense

Simulate requirement clarification, interviewer follow-ups, architecture narration, and tradeoff defense. Add voice after text mocks are reliable.

Acceptance: a 45-minute mock produces an evidence-linked report across the same rubric used by guided practice.

Readiness Dashboard and Portfolio

Replace XP-as-ability with skill evidence, trend lines, completed independent designs, weak areas, and readiness by interview level.

Acceptance: every score links to attempts that support it; completing lessons alone cannot produce an “interview ready” status.

Release gates

Gate 0 · Activation works

Fix 00 complete. The first session produces a visible system-design win within five minutes, requires no hidden prior knowledge, and ends with a concrete artifact and an accurate explanation.

Gate 1 · Useful prototype

Fixes 01–02 complete. A learner can independently design one system and receive reproducible rubric feedback.

Gate 2 · Learning product and permission to build Expo

Fixes 03–06 complete in HTML. At least 10 polished foundational units, 3 guided designs, adaptive review, and causal simulations help you learn and apply the material. Expo work begins after this gate; no recruited cohort is required.

Gate 3 · Paid mobile launch

The proven learning system runs reliably in Expo with offline progress, accessibility, saved designs, diagnostic onboarding, and a restrained learning-first reward loop. Test $9.99/month and $79.99/year.

Gate 4 · Expanded product

At least 10 deep capstones and 8 simulations/labs, plus reliable contextual evaluation, timed mocks, and evidence-linked readiness reporting. Expert review is a useful late sanity check, never a building dependency.
