Stackling · controlled backlog

Topics worth adding later

This is not permission to keep expanding the course. The current 44-unit path ships first. A topic moves from this page into the curriculum only when it teaches a capability the existing units cannot teach by becoming deeper.

Gate: improve complete request paths, schemas, failure injection, architecture revision, and design review in the existing studios before adding another unit.

Highest-value extensions

P1 · concurrency

Distributed locks and fencing tokens

Lease expiry, stale owners, fencing tokens, and why a lock without enforcement cannot protect an external resource.

  • Prerequisites: Consensus, Idempotency
  • Best format: competing-owner simulation
P1 · data movement

Change Data Capture

Reading committed database changes into streams without inventing an unsafe application dual write.

  • Prerequisites: Transactions, Event Streams
  • Best format: outbox versus log-based CDC lab
P1 · retrieval

Search systems and inverted indexes

Tokenization, postings lists, relevance, indexing lag, shard fan-out, and deletion from derived search state.

  • Prerequisites: Indexes, Sharding, Consistency
  • Capstone candidate: product search
P1 · execution

Batch processing and workflow orchestration

Durable workflow state, retries, compensation, backfills, scheduling, and work that outlives one process.

  • Prerequisites: Queues, Idempotency, Streams
  • Best format: failed multi-step workflow

Valuable after the first release

P2 · storage

Object storage internals

Chunking, erasure coding, metadata, checksums, repair, multipart upload, and why object stores do not behave like mounted disks.

P2 · analytics

Warehouses and analytical systems

Columnar storage, partition pruning, batch ingestion, materialized views, and separating operational from analytical workloads.

P2 · probability

Bloom filters and probabilistic structures

Trading bounded false positives for memory and I/O savings without pretending approximation is exactness.

P2 · economics

Cost-aware architecture

Model bandwidth, storage, requests, idle capacity, replication, and operational labor as design constraints.

P2 · governance

Privacy, deletion, and data residency

Purpose limitation, regional placement, deletion propagation, backup retention, audit evidence, and derived-data cleanup.

P2 · platform

API gateways and service meshes

Separate edge policy from service-to-service policy and identify when platform indirection solves more than it obscures.

Admission test

A proposed unit must answer all four questions:

  1. What capability is absent from the current 44 units?
  2. Which earlier units are prerequisites?
  3. What interactive system can a learner manipulate?
  4. Which existing unit cannot absorb this material without losing coherence?

Pass all four: schedule it. Fail any: deepen an existing unit instead.
